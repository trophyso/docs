Here you'll integrate your application with Trophy and start building your first gamified feature.

<Tabs>
  <Tab title="Using AI" icon="bot">
    These instructions are for using Trophy with AI assistants that support MCP — for example Claude, ChatGPT, Cursor, or Claude Code.

    <Steps>
      <Step title="Create your Trophy account">
        First, [create a new account](https://app.trophy.so/sign-up?utm_source=docs&utm_medium=quickstart) if you don't have one already. Complete onboarding to get your account set up.
      </Step>

      <Step title="Connect Trophy MCP servers">
        Connect both Trophy MCP servers in your AI client for the best experience:

        - Docs MCP server URL: `https://docs.trophy.so/mcp` (live documentation context)
        - Account MCP server URL: `https://mcp.trophy.so/mcp` (account actions — OAuth sign-in required)

        Setup guides: [Docs MCP installation](/mcp/docs-mcp-server/installation), [Account MCP installation](/mcp/account-mcp-server/installation).

        <Tip>
          Use the [Docs MCP](/mcp/docs-mcp-server/introduction) as on-demand docs context and the [Account MCP](/mcp/account-mcp-server/introduction) for account changes. Use both for [best practice](/mcp/best-practice).
        </Tip>

      </Step>
      <Step title="Ask your AI to perform initial setup">
        Here's a prompt you can use with your AI assistant to perform initial Trophy setup:

        <Prompt
          description="Perform initial Trophy setup"
          icon="paperclip"
          iconType="solid"
          actions={["copy", "cursor"]}
        >
          I'm adding gamification to my app using Trophy.

          Before making changes, verify the connected Trophy MCP Servers are available. Use the Docs MCP server as the primary source of truth for Trophy integration details, and the Account MCP server to configure my account.

          1. Detect the backend language/framework in this repo and install the relevant official Trophy SDK (or use HTTP calls if no SDK is available). Report to Trophy support if no SDK is available.

          3.           4. Add basic error handling and logging around Trophy SDK calls.
          5. Add or update a short README section explaining how the integration works and how to extend it.

          Constraints:
          - Use Docs MCP tool results for all Trophy-specific implementation decisions and integrations.
          - Do not rely on prior memory for Trophy SDK behavior when MCP provides an answer.

          - Show a concise summary of changed files and how to test the setup.
          - Suggest next steps based on the gamification features Trophy supports and the use case.
        </Prompt>

        This will:

        1. Add the relevant [Trophy SDK](/api-reference/client-libraries) to your app based on your tech stack
        2. Add a new `TROPHY_API_KEY` variable to your environment settings
        3. Add code to track metric events for the chosen user activity using the Trophy SDK client - required for all gamification features.
      </Step>
      <Step title="Build your first gamification feature">
        Once initial setup is complete, pick a common use case and paste the matching prompt into your AI assistant:

        <Prompt
          description="Daily streak"
          icon="paperclip"
          iconType="solid"
          actions={["copy", "cursor"]}
        >
          Build a daily streak feature with Trophy.

          Use the Docs MCP as the source of truth for how streaks work, and the Account MCP to configure my account.

          Goals:
          1. Drive the streak from a core user activity already tracked (or that we should track) as a Trophy metric.
          2. Ensure every user identify/upsert and metric event includes the user's `tz` attribute (IANA timezone). This is required for streaks to evaluate calendar days correctly for each user.
          3. Configure the streak featuer in Trophy using a sensible threshold for the chosen metric.
          4. Enable streak freezes and streak pauses if they fit this product; otherwise omit them and say why.
          5. Wire any app-side reads or UI needed to show the user's current streak, freezes, and pause state.
          6. Summarize what was configured, what code changed, and how to verify the streak end to end. Explicitly explain back why sending `tz` matters for a functioning streak feature.
        </Prompt>

      <Step title="Create your Trophy account">
        First, [create a new account](https://app.trophy.so/sign-up?utm_source=docs&utm_medium=quickstart) if you don't already have one and head into the [Trophy dashboard](https://app.trophy.so).

        Head through onboarding to get your account set up.

      </Step>
      <Step title="Add the Trophy SDK to your backend">
        We have SDK libraries available in most major programming languages but if you don't see yours listed, let us know and we'll make one!

        <SdkInstallCommand />

        Alternatively, you can directly call the API using any server-side HTTP client.

      </Step>
      <Step title="Set up environment">
        Head to the [integration page](https://app.trophy.so/integration) of the Trophy dashboard and create a new API key.
        
        Add your API key as an environment variable in your backend application:

        <AddEnvVarBlock />

        Then initialize the Trophy API client in your backend using that API key:

        <TrophyClientInitBlock />

        Make sure all Trophy SDK calls use this client for authentication.
      </Step>
      <Step title="Create your first metric">
        All gamification features are driven by user interactions. In Trophy, you use [Metrics](/features/metrics) to define and model those interactions and [Events](/features/events) to track them.
        
        Here you'll create your first metric to get started. In the Trophy dashboard, head into the [metrics page](https://app.trophy.so/metrics) and hit the _New Metric_ button:

        <Frame>
          <video
            autoPlay
            muted
            loop
            playsInline
            className="w-full aspect-video"
            src="../assets/features/metrics/create_new_metric.mp4"
          ></video>
        </Frame>

        Give the metric a name and hit _Save_.

      </Step>
      <Step title="Integrate the metric into your backend">
        Once you've created your metric, head to the configure tab and copy it's unique API reference key.

        <Frame>
          <video
            autoPlay
            muted
            loop
            playsInline
            className="w-full aspect-video"
            src="../assets/quick-start/copy_metric_key.mp4"
          ></video>
        </Frame>

        To track an event against this metric when a user interacts with your product, call the [metric change event API](/api-reference/endpoints/events/submit-a-metric-event), passing along details of the user that made the interaction. In this example the metric key would be `flashcards-flipped`:

        <MetricChangeRequestBlock />

        By making this call, you're telling Trophy that a specific user made an interaction with your product. As a result, Trophy will process any gamification features like achievements or streaks that you've configured against the metric automatically.

      </Step>
