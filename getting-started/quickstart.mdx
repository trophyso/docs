Here you'll integrate your application with Trophy and send your first metric event in about five minutes. Everything in Trophy is powered by the user activity you send as events, so this is the first step whatever you're building.

  <Tab title="Using AI" icon="bot">

    <Steps>

      <Step title="Connect Trophy MCP servers">
        Connect both Trophy MCP servers in your AI client for the best experience:

        - Docs MCP server URL: `https://docs.trophy.so/mcp` (live documentation context)

        Setup guides: [Docs MCP installation](/mcp/docs-mcp-server/installation), [Account MCP installation](/mcp/account-mcp-server/installation).

        <Tip>
          Use the [Docs MCP](/mcp/docs-mcp-server/introduction) as on-demand docs context and the [Account MCP](/mcp/account-mcp-server/introduction) for account changes. Use both for [best practice](/mcp/best-practice).
        </Tip>

      </Step>
      <Step title="Ask your AI to perform initial setup">
        Here's a prompt you can use with your AI assistant to perform initial Trophy setup:

        <Prompt
          description="Perform initial Trophy setup"
          icon="paperclip"
          iconType="solid"
          actions={["copy", "cursor"]}
        >
          I'm integrating Trophy into my app.

          Before making changes, verify the connected Trophy MCP Servers are available. Use the Docs MCP server as the primary source of truth for Trophy integration details, and the Account MCP server to configure my account.

          Please do the full initial setup end-to-end:
          1. Detect the backend language/framework in this repo and install the relevant official Trophy SDK (or use HTTP calls if no SDK is available). Report to Trophy support if no SDK is available.
          2. Add `TROPHY_API_KEY` to environment config in a secure way (no secrets committed to git), and wire it into the Trophy SDK client initialization.
          3. Add code to set up metric event tracking for the chosen user activity (ask if not known yet) using the Trophy SDK client, wiring all required user attributes like ID, and using placeholders for all optional attributes like name, email, tz and signUpDate, unless already known or required by the use case.
          4. Add basic error handling and logging around Trophy SDK calls.
          5. Add or update a short README section explaining how the integration works and how to extend it.

          Constraints:
          - Use Docs MCP tool results for all Trophy-specific implementation decisions and integrations.
          - Do not rely on prior memory for Trophy SDK behavior when MCP provides an answer.
          - Keep secrets out of source control.
          - Use existing project patterns and naming conventions.
          - Show a concise summary of changed files and how to test the setup.
          - Suggest next steps based on my use case: agentic messaging, in-app features, or both.
        </Prompt>

        This will:

        1. Add the relevant [Trophy SDK](/api-reference/client-libraries) to your app based on your tech stack
        2. Add a new `TROPHY_API_KEY` variable to your environment settings
        3. Add code to track metric events for the chosen user activity using the Trophy SDK client - required for all Trophy features.

        Once your first event is sent, see [next steps](#next-steps) to choose what to build.
      </Step>

In this example the metric key would be `flashcards-flipped`:

        <VerifiedFirstEvent />

        By making this call, you're telling Trophy that a specific user made an interaction with your product. Trophy records the user's activity and automatically processes anything you've configured against the metric.

        <Tip>
          Include the user's `email` and `tz` (IANA time zone) attributes where you can. Trophy uses them to reach users and to work out each user's local day.
        </Tip>
